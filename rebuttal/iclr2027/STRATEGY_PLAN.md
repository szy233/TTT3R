## 证据计划

所有实验都用同一 checkpoint，不改训练，结果按场景配对：Wilcoxon + bootstrap 95% CI。同一配置的两次运行相差 0.5–2.2%（最大的是 TUM 0.0545 对 0.0557，后者是更早的代码版本），小于这个幅度的差异按持平处理。

运行时间按约 10 FPS 估算；现在两张卡的利用率都是 100%，实际可能更慢。

### E1 — 同范数、不分解方向（核心）

**回答：** R2-Q1、R2-C1、R1-C3、R3-C1

**做法：** 新增 `ddd3r_normmatch`，对每个 token 算 `g_t = ‖α⊥δ⊥ + α∥δ∥‖ / ‖δ‖`，然后用 `g_t·δ` 更新。范数与 ortho 逐 token 相同，方向与原始 δ 相同。其余步骤和 ortho 一致。

**数据：** TUM 1000f、ScanNet 1000f、ARKitScenes 500f。约 3.2 GPU 小时。

**运行前登记的预测：**
- P1：TUM 上 ortho 优于 normmatch。
- P2：ScanNet 和 ARKitScenes 上 normmatch 优于 ortho。

**结果怎么写：**

| 结果 | 含义 | 论文的说法 |
|---|---|---|
| P1、P2 都成立 | 方向确实有独立作用，正负由漂移能量决定 | 保留方向分解的主张，范围限定在低漂移场景 |
| P1 不成立，TUM 上二者持平 | 增益来自逐 token 的幅度，不是方向 | 明确承认。贡献转为诊断和幅度调节，方向分解降为被检验过的假设 |
| TUM 上 normmatch 反而更好 | 方向分解没有好处 | 同上，并建议用 normmatch 取代 ortho |

### 2026-11-07 E5b 裁定

详情见 `docs/PREREG_E1_E5.md` 末尾。

- **撤回：** “best aggregate for outdoor driving” 和 “our strongest test of domain shift”。ortho 均值最低，但 ATE 上只胜过 CUT3R，与 TTT3R、const、brake 都打平。
- **可以说：** ortho 的 r_rel 优于其余四种方法，代价是逐帧 RPE trans 为 CUT3R 的 2.8 倍；所有方法的绝对误差都很大（t_rel 超过 50%）。
- **对 T3 的影响：** KITTI 不再支持排名反转。反转的证据只剩 TUM 和 ScanNet，ARKitScenes 单独看。
- **新错误 S12：** 表 5 的 const 行在 KITTI 两列用的是 α=0.33。

### 2026-11-08 E7 裁定

详情见 `docs/PREREG_E7.md` 的日期节。固定每个 token 的步长为 const α 的步长，只换方向。

- **P7a 不成立：** TUM 三个尺度都打平（p≥0.31）。同范数那句要限定为 ortho 自己的范数调度。
- **P7b 成立：** KITTI r_rel 三个尺度方向都更好（p≤0.014），差距大于 13.4% 的舍入噪声。代价是 α=0.10 的 ATE、α=0.10 和 0.20 的 RPE 平移更差。因 TUM 打平，只能逐格报告，不能概括成“方向和尺度叠加”。
- **P7c 不成立：** ScanNet 两个尺度方向都更差，害处不随步长变小。ARKitScenes 在 0.10、0.20 方向更差，0.33 打平。
- **平标量：** const 0.10 在四个数据集的主指标上都不比 ortho 差，ScanNet 上更好。必须在讨论方向的回复里明说。
- **舍入噪声（Amendment 1）：** 1e-7 的扰动让均值最多变 4.7%（TUM ATE）、6.9%（KITTI ATE）、13.4%（KITTI r_rel），2.2% 不再称为“最大差距”。TUM 上 brake 对 const 0.33、KITTI 上 α∥=0.15 对 brake 这两个“更好”都在噪声以内。
- **对立场的影响：** 方向的独立作用只在一个数据集的一个指标上稳定出现（KITTI 旋转误差，各步长都成立，但有平移代价），TUM 上的增益不能归给方向本身，ScanNet 和 ARKitScenes 上方向有害。论文定位应是“过量更新的诊断 + 标量阻尼”，方向分解作为一个经过检验、作用随数据集而变的控制轴。

### 2026-11-07 E6、E6d 裁定

详情见 `docs/PREREG_E6.md`、`docs/PREREG_E6D.md` 的日期节。

- **E6a：** 同范数下，方向降低 KITTI 的 r_rel（11.88 vs 16.78，10/11，p=0.019）。ATE、t_rel 打平，RPE 平移更差（0/11）。
- **E6b、E6d：** 不成立。α=0.10–0.20 的平标量在 TUM 和 KITTI r_rel 上都与 ortho 打平，KITTI 的最低均值在扫描边界 α=0.10。不能写成只有分解才做得到。
- **E6c：** 四项全部成立。α∥=0.15 时 TUM 的方向收益还在，ScanNet 的害处缩小但未消失，ARKitScenes 和 KITTI 的样本外预测成立。KITTI r_rel 不如默认值，默认值不变。
- **对 E4 的修正：** 同代码下，brake 在 TUM 上略好于常数 0.33（0.0634 vs 0.0648，p=0.039），ScanNet 仍打平。brake 相对 const 0.5 的差距大部分来自尺度，不再说全部。
- **对立场的影响：** 分解是可单独测试的控制轴，同范数下有可测的独立作用，符号随数据变化，记录了 ScanNet 的失败。它不是普遍更好的方法，也不是达到这些结果的唯一途径。
