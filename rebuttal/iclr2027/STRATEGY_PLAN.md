## 证据计划

所有实验都用同一 checkpoint，不改训练，结果按场景配对：Wilcoxon + bootstrap 95% CI。同一配置的两次运行相差 0.5–2.2%（最大的是 TUM 0.0545 对 0.0557，后者是更早的代码版本），小于这个幅度的差异按持平处理。

运行时间按约 10 FPS 估算；现在两张卡的利用率都是 100%，实际可能更慢。

### E1 — 同范数、不分解方向（核心）

**回答：** R2-Q1、R2-C1、R1-C3、R3-C1

**做法：** 新增 `ddd3r_normmatch`，对每个 token 算 `g_t = ‖α⊥δ⊥ + α∥δ∥‖ / ‖δ‖`，然后用 `g_t·δ` 更新。范数与 ortho 逐 token 相同，方向与原始 δ 相同。其余步骤和 ortho 一致。

**数据：** TUM 1000f、ScanNet 1000f、ARKitScenes 500f。约 3.2 GPU 小时。

**运行前登记的预测：**
- P1：TUM 上 ortho 优于 normmatch。
- P2：ScanNet 和 ARKitScenes 上 normmatch 优于 ortho。

**结果怎么写：**

| 结果 | 含义 | 论文的说法 |
|---|---|---|
| P1、P2 都成立 | 方向确实有独立作用，正负由漂移能量决定 | 保留方向分解的主张，范围限定在低漂移场景 |
| P1 不成立，TUM 上二者持平 | 增益来自逐 token 的幅度，不是方向 | 明确承认。贡献转为诊断和幅度调节，方向分解降为被检验过的假设 |
| TUM 上 normmatch 反而更好 | 方向分解没有好处 | 同上，并建议用 normmatch 取代 ortho |

### E2 — 投影方向时序

**回答：** R3-Q2a。新增 `ddd3r_prevdir`，先投影到 d_{t-1} 再更新 EMA。TUM + ScanNet 1000f，约 3 GPU 小时。不登记方向性预测，照实报告。

### E3 — token 层面的时间自适应

**回答：** R1-C4。分两步：
- (a) 统计 TTT3R 的 β_t 单 token 时间标准差。
- (b) 功能测试：先跑一遍取每个 token 的时间均值，再用这个固定值替代 β_t 重跑。

TUM 全部 + ScanNet 按名称排序前 20 个场景，约 1.5 GPU 小时。

**预测：** 冻结后 ATE 不变差。如果明显变差，就撤回 “provides no real temporal adaptivity”，把诊断收窄到帧平均层面。
